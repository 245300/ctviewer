# CTViewer 下一步升级建议（2.19.1 基线）

> 写于 2026-11-26，2026-11-27 更新到 2.19.1。
> **项目定位：个人本地使用，不发布、不分发、不做安装包。** 下面只列「本地玩得更好」的方向，
> 不包含任何发布 / 分发 / 上架相关工作。

## 2. 还可以做（按投入产出排序）

### 2.1 驾驶玩法深化（性价比最高的一块）

- 计时赛：在广场 / 街区设起点、检查点、终点，用现有 `DrivingMode.pos` 判定，HUD 复用速度表；
- 巡逻点 / 障碍物：把城市占位网格里的空地标成路线，放几个可撞倒的锥桶（纯视觉，不引入物理引擎）；
- 下车点保持：现在下车固定回展位，可以让车停在城里、人物从车旁下车，下次 `E` 再上车。
- 工作量：中（主要改 `js/drive.js` + `js/main.js` 的 HUD）。

### 2.2 城市二级 LOD

- 中心街区 19.2 万面在室内也全量渲染；给 10 个材质桶各生成一份 20% 面数的 `city.lod.glb`，
  相机距中心 > 80 m 时整体替换（室内看窗外基本无感）。
- 必须用 `inspect` 实测减面结果，别信 `simplify --ratio`。
- 工作量：中（构建脚本 + `city.js` 切换），预期再省 10 万面左右。

### 2.3 纹理与显存（KTX2）

- 道具 / 人物 / 车的贴图转 KTX2（Basis）：显存降 4–6 倍，切车不再卡在解码；
- `vendor/` 补 `basis_transcoder.js/wasm`，GLTFLoader 注册 `KTX2Loader`；
- 车漆的 clearcoat / normal 保持 1K，别升 2K（Iris Xe 吃不消）。
- 工作量：中，要动构建链与加载器。

### 2.4 静态合批余项

- 21 件道具已按材质合批；车库程序化陈设（约 55 个 mesh）同样可合，灯带单独留（要开关）。
- 预期道具 + 陈设 draw call 从 ~120 降到 ~20。

### 2.5 画质档位

- 现有 `?q=low|medium|high` 与动态分辨率已经够用；若继续做，就把「降档」从一次性改成
  「连续 2 s < 45 FPS 降一档」，并在设置里给「锁定档位」开关（截图 / 演示时不想被自动降）。

### 2.6 内容扩充

- 车库继续加陈设：霓虹招牌、轮胎品牌墙、工具挂板、气瓶、洗车机；仍走 `build/build_props.sh`
  的 CC0 管线，单件 < 1 MB。
- 广场加几个可交互点（咖啡车、路牌、长椅坐姿），让「探索」有目的地。
- 车型库只在拿到明确许可后扩；每台车必须过 `tools/car_orient.html` 的朝向与
  `scripts/build_models.py` 的包围盒体检，坏模型直接不入库。

## 3. 工程质量（持续做，不占版本）

| 项 | 做法 | 收益 |
| --- | --- | --- |
| 视觉回归 | Playwright 对 5 视角 × 3 车 × 2 场景截图，pixelmatch 阈值 2% | 防止“改 A 坏 B” |
| 性能预算 | CI 断言三角面 < 300 万、draw call < 700、首屏 < 2.5 s | 防止资产悄悄变重 |
| 碰撞升级 | AABB → 胶囊 vs OBB，加 0.25 m 台阶高度 | 8.8 m/s 跑动不再被 1 m 网格卡住 |
| 资产校验 | 每台车入库前自动量 bbox / minY / 零件数 / Draco | 坏模型进不来 |
| 版本一致性 | 4 处版本号 + SW 缓存名由脚本一起改 | 不再手改漏一处 |

## 4. 不建议现在做

- **WebGPU 重写**：three r169 的 WebGL2 路径在 Iris Xe 上是够的，瓶颈是填充率不是 API。
- **引入 cannon / rapier 物理引擎**：一辆车的街机驾驶用运动学 + 滑动就够，物理引擎只会增加包体与调参成本。
- **4K / 8K 贴图**：集显显存和带宽都吃不消，视觉收益远小于 KTX2 + 合批。
- **继续堆未授权车型 / 人物**：本地库已经够用，再加只会让素材体检与加载成本变重。
